### **2. SOLID Principles Implementation**

Your project demonstrates **excellent SOLID adherence**:

#### **S - Single Responsibility Principle** ✅
- Each class has one clear responsibility:
  - `SignUpController` - handles HTTP request/response for signup
  - `DbAddAccount` - orchestrates account creation use case
  - `BcryptAdapter` - handles encryption only
  - `AccountMongoRepository` - manages account persistence

#### **O - Open/Closed Principle** ✅
- Classes are open for extension, closed for modification
- New validators, repositories, or encrypters can be added without changing existing code
- Example: Can add `JWTAdapter` alongside `BcryptAdapter` without modifying either

#### **L - Liskov Substitution Principle** ✅
- All implementations can be substituted for their interfaces:
  - `BcryptAdapter` implements `Encrypter` interface
  - `AccountMongoRepository` implements `AddAccountRepository`
  - `EmailValidatorAdapter` implements `EmailValidator`

#### **I - Interface Segregation Principle** ✅
- Interfaces are small and focused:
```typescript
export interface Encrypter {
    encrypt(value: string): Promise<string>;
}

export interface AddAccountRepository {
    add(accountData: AddAccountModel): Promise<AccountModel>
}
```

#### **D - Dependency Inversion Principle** ✅ ⭐
**This is exceptionally well implemented:**
- High-level modules (Domain/Data) don't depend on low-level modules (Infra)
- Both depend on abstractions (interfaces)
- Dependencies flow inward toward the domain

**Example:**
```typescript
// Data layer depends on interface, not concrete implementation
export class DbAddAccount implements AddAccount {
    constructor(
        private readonly encrypter: Encrypter,  // Interface, not BcryptAdapter
        private readonly addAccountRepository: AddAccountRepository  // Interface
    )
}
```

### **3. Design Patterns Observed**

#### **Dependency Injection** ⭐
```typescript
// Factory pattern composing dependencies
export const makeSignUpController = (): SignUpController => {
    const emailValidatorAdapter = new EmailValidatorAdapter();
    const bcryptAdapter = new BcryptAdapter(12);

}
```

#### **Adapter Pattern**
- `BcryptAdapter` - adapts bcrypt library to your `Encrypter` interface
- `EmailValidatorAdapter` - adapts validator library to your `EmailValidator` interface
- `ExpressRouteAdapter` - adapts Express to your `Controller` interface

#### **Repository Pattern**
- `AccountMongoRepository` abstracts data access
- Domain doesn't know about MongoDB specifics

#### **Factory Pattern**
- `makeSignUpController()` encapsulates object creation complexity
